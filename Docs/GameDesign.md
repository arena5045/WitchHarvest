# 마녀의 수확제 — 게임 기획

기준: 2026-11-25 / 개발 버전 0.45. 이 문서는 개발자가 합의한 방향과 최신 구현을 연결하기 위한 요약이다. 실제 구현 상태는 [DevelopmentStatus](DevelopmentStatus.md), 아트는 [ArtDirection](ArtDirection.md)를 참고한다. 세부 이야기 대본과 최신 노드 도식은 별도로 관리하며, 공개 저장소에 미공개 반전은 기록하지 않는다.

## 1. 게임 정체성

- 제목: 마녀의 수확제 (WitchHarvest, 가제).
- 장르: 짧은 라운드 반복형 인크리멘털 / 수확 중심 성장 게임. Steam PC 출시 목표.
- 플레이타임 목표: 약 3~6시간. 가격, 출시일과 최종 콘텐츠 수는 미확정.
- 한 줄 콘셉트: 견습 마녀가 이모의 별장에서 요괴 작물을 수확하고, 영구 강화를 통해 점점 거대한 수확 마법을 펼친다.
- 제작의 최우선 목표: 규모가 작아도 완결된 게임을 실제로 출시한다. 콘텐츠 수·가격·대기 시간만 부풀려 분량을 채우지 않는다.
- 재미의 핵심: 처음 몇 개만 수확하던 플레이어가 농장 확장, 마법 속도·범위·연쇄 효과, 사역마를 통해 화면 전체를 풍성하게 수확하는 시각적 성장. 단순한 숫자 증가보다 플레이가 변하는 해금을 중시한다.

복잡한 농장 경영, 계절, 건축, 교배, 호감도, 전투, 대규모 제작 시스템을 기본 사양으로 삼지 않는다. 공방 가공 및 판매는 본편 완성 후 검토하는 업데이트 후보이다.

## 2. 세계관 및 인물

귀엽고 유쾌한 판타지. 마녀와 악마 소재를 사용하더라도 공포·고어·무거운 비극이 중심이 아니다.

- 리엘(Riel): 대마녀 레니아의 조카인 견습 마녀. 이모가 준 별장에서 연금술 재료가 되는 요괴 작물을 수확하며 성장한다.
- 세르(Ser): 별장과 농장을 관리해 온 대악마. 레니아의 옛 사역마이자 오랜 친구로 리엘을 보좌한다. '괴물의 얼굴을 한 신사'라는 대비가 핵심. 리엘을 '아가씨'라 부르며 존댓말을 쓰고, 정중하고 연륜 있는 태도에 능글맞은 농담을 섞는다. 가끔 화면 밖 플레이어를 인식한다. 제4의 벽 농담은 남발하지 않는다.
- 레니아(Lenia): 고대 마법과 연금술에 통달한 리엘의 이모. 상냥하고 능글맞지만 공과 사를 분명히 구분한다. 세르와는 오랜 친구로 대등한 관계다.

인트로, 튜토리얼, 낮 시작/종료, 특정 작물·노드 해금 및 기타 조건에서 짧은 만담이 발생한다. 스킵과 다시보기를 지원하는 방향. 구체적인 조건·대본과 미공개 인물 설정은 별도 기획 자료에서 관리한다.

## 3. 확정된 하루의 루프

1. 하루 시작 시 모든 배치 작물이 수확 가능한 상태다. 플레이어는 직접 씨앗을 심지 않는다.
2. 제한시간 동안 마우스 커서를 움직인다. 커서의 원형 마법 영역이 일정 간격으로 공격하여 범위 안의 모든 작물 HP를 감소시킨다. 별도 클릭은 필요 없다.
3. HP가 모두 감소한 작물은 즉시 수확량에 반영되며 수확 연출 후 제거된다.
4. 낮이 끝나면 수확한 작물만 판매하고 결과창을 표시한다. 다 수확해도 기본적으로 제한시간은 끝까지 진행된다.
5. 밤(로비)에서 골드로 영구 강화 노드를 구매한다.
6. 다음 날 버튼을 누르면 이전 작물을 정리하고 모든 농장 칸에 새 작물을 준비한 후 다음 날짜를 진행한다.

수확하지 못한 작물은 대악마가 처리한다는 세계관 설명이며 현재 구현에서는 판매되지 않는다. 기본 작물은 그날 자연 재생하지 않는다. 관련 강화를 해금한 뒤의 조건부 재성장은 별도 효과다.

초반 1×1 농장의 도망무로 시작해 첫 판매금으로 2×2 확장을 경험하는 방향. 프로토타입은 카운트다운 3초, 수확 10초이지만 최종 밸런스가 아니다. 이후 최대 농장 크기, 라운드 시간과 강화 가격 등은 검증 후 조정한다.

## 4. 강화와 성장

선행 조건을 만족하는 가지에서 골드로 노드를 구매하는 자유 성장형 트리. 다른 가지를 영구히 포기해야 하는 배타적 빌드나 진행이 영구적으로 막히는 조건을 지양한다. 현재 구현된 노드는 농장 2×2와 수확 속도(3레벨)이다. 실제 노드 연결과 가격은 SO를 기준으로 한다.

추후 설계 방향(아래는 구현 지시가 아니라 검토 대상):

| 시스템 | 설계 의도 |
| --- | --- |
| 농장 확장 | 수확 가능한 칸 증가. 수확 성능과 함께 성장시킨다. |
| 수확 능력 | 속도, 피해량, 범위, 연쇄 효과. 후반에는 크리티컬 확률 100% 및 높은 배율에 도달하는 성장 경로를 검토한다. |
| 작물 해금 | 새로운 요괴 작물과 수익/특수효과. 정확한 등장 비율·등급·가격은 미정. |
| 조건부 재성장 | 해금 후 수확한 빈칸에서 확률적으로 작물이 다시 자란다. 즉시 완성되지 않고 성장 대기시간을 가진다. |
| 사역마 독립 재배 | 메인 밭과 별도의 화면 하단 공간에서 수확 → 성장 → 수확을 반복하는 자동화 구상. |
| 성장 시간 감소 | 메인 밭의 해금형 재성장과 사역마 재배 주기에 적용하는 방향. |
| 추가 수확 확률 | 작물 하나를 수확했을 때 두 개 분량을 얻는 확률. 빈칸에 재성장시키는 효과와 다르다. |
| 잡초와 제초 사역마 | 잡초 감소 강화 이후에도 최소 5~10% 정도 남도록 하는 의도. 사역마가 수익이 없는 잡초를 제거해 새 작물의 등장 기회를 만든다. 수치는 테스트 전 방향. |
| 숙련 할인 | 특정 작물의 누적 수확량에 따라 관련 노드 구매 비용을 할인하는 후보. 정가 구매 가능성을 유지해 하위 작물 미등장 때문에 진행이 막히지 않게 한다. |

추가 수확의 누적 기록 반영, 재성장의 트리거와 시간, 제초 후 재배 조건, 구체적 크리티컬 경로, 숙련 할인 여부와 수치는 미확정이다. 자동화는 수동 조작의 재미를 없애지 않는 방향을 우선한다.

작물 후보: 도망무(기본), 잡초, 폭탄 호박(연쇄 효과 후보), 번개 콩(연쇄 효과 후보), 수정꽃(고가치 후보), 거대 요괴 식물(후반 후보). 도망무를 제외한 실제 효과와 목록·등급 체계는 아직 확정 구현이 아니다. 포션과 공방은 당장 구현하지 않는다.

## 5. 세이브와 회고록 — 확정 규칙

| 파일 | 저장 시점 | 데이터 및 복귀 |
| --- | --- | --- |
| Progress.json | 낮 수확 종료 후 판매금 지급 완료 시에만 | 완료 일차, 보유 골드, 구매한 노드 ID/레벨. 로드하면 그 날짜의 밤으로 진입. |
| Memoir.json | 새로운 정상 대화 재생 시작 시 | 발견한 대화 ID. 회고록 해금은 진행 롤백과 독립적으로 유지. |

밤의 구매나 다음 낮 도중의 진행은 다음 낮 종료 전에는 저장되지 않는다. 잘못 구매했다면 게임을 종료하고 마지막 낮 종료 상태로 돌아갈 수 있다. 게임 종료나 노드 구매 시 진행 자동 저장을 추가하지 않는다. 첫날 낮 종료 전에는 진행 파일이 없을 수 있다.

예: DAY 5 낮 종료 → 밤에 노드 구매 및 새 대화 발견 → DAY 6 수확 중 종료 → DAY 5 밤과 구매 전 골드/강화로 복귀하되, 새 대화는 회고록에 남는다.

저장 파일에는 SO나 파생 스탯을 통째로 저장하지 않는다. 고유 ID로 원본을 참조한다. 대화 해금과 실제 게임 내 이벤트 실행 여부는 서로 다른 정보이며, 회고록 해금만으로 이벤트 재생 여부를 결정하지 않는다. 회고록 다시보기에서 보상이나 진행 이벤트를 재실행하지 않는다.

## 6. 타이틀, 회고록과 엔딩 방향

타이틀 메뉴는 게임 시작 / 옵션 / 회고록 / 나가기. 게임 시작은 기존 진행 파일을 복원하거나 새 게임을 시작한다. 옵션과 회고록은 타이틀 내부 패널로 접근한다. 회고록은 발견한 대화를 다시 보며 작물·인물·세계관 자료를 수집하는 재미를 제공하는 방향이다. 실제 도감 범위와 해금 조건은 별도 결정한다.

완결된 최종 목표와 엔딩을 제공한다. 성장과 대화 수집이 결말에 의미 있게 연결되는 방안을 검토 중이다. 강제 반복 플레이로 시간을 늘리지 않는다. 구체적인 엔딩 분기, 조건, 스토리 대사, 복귀/저장 규칙은 미확정 또는 비공개이므로 별도 합의 없이 구현하지 않는다.

## 7. 기획 운영

'확정 규칙', '현재 구현', '검토 중'을 구분한다. 프로토타입 수치를 출시 사양으로 취급하지 않고, 초기 예시 노드 트리를 최신 사용자 편집 도식으로 간주하지 않는다. 세부 세계관, 미공개 대본과 최신 상세 노드 도식은 개발자가 관리하는 별도 기획 자료를 우선 확인한다.
